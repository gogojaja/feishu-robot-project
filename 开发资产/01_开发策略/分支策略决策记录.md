# 分支策略决策记录 — 飞书机器人项目

> 开发策略环节 1　版本：v0.1　2026-08-05

## 决策

采用 **Trunk-Based Development（主干开发）**：单一 `main` 主分支，小步提交，短生命周期。

## 理由

| 维度 | Trunk-Based（选定） | Git Flow |
|------|---------------------|----------|
| 协作规模 | 单开发者单机 | 多人并行 |
| 提交频率 | 高频小步 | 低频批次 |
| 复杂度 | 极低 | 高（多分支） |
| 环境适配 | test 单机 | 多环境 |
| 回滚 | git revert 即可 | 分支管理成本高 |

## 规则

1. 每次 commit 为可编译完整代码，不提交半成品
2. 功能缺口逐条完成（T1-T6），单线串行
3. 提交前本地语法自检 + 环境核验
4. 分支策略固化后不可随意变更（变更走 change_audit）
