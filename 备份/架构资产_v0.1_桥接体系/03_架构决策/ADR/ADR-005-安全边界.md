# ADR-005 安全边界：最小权限 + 凭证内存态 + open_id 隔离

> 状态：已接受　类型：安全架构　日期：2026-08-05
> 架构阶段：环节 3（record_decisions）

## 背景

系统对接飞书开放平台需管理 app_secret 与 tenant_access_token，并暴露事件回调接口。需确定安全边界策略。

## 决策

- **凭证管理**：app_id/app_secret 存 config/feishu.yaml（环境变量优先），仅内存态加载；token 过期自动刷新，连续失败≥3 次告警。
- **权限最小化**：仅申请 token 获取、消息发送、私聊/群@读取等最小 API 权限；全程禁 sudo、禁 /Users/gogo 路径。
- **隔离**：按 open_id 键控会话，禁止跨用户串访；入站 >4KB 拒绝；open_id 级限流。
- **日志**：凭证不写入日志与响应体；消息正文不落盘。

## 权衡

| 维度 | 决策 | 备选 |
|------|------|------|
| 凭证存储 | YAML+环境变量，内存态 | 硬编码（拒绝）/外部 KMS（过度） |
| 会话隔离 | open_id 键控 | 全局共享（违规） |
| 传输安全 | HTTPS + 飞书验签 | 明文（拒绝） |

## 理由

- REQ-SEC-REQ-001~004 全部 Must 级强制；AGENTS.md 环境约束铁律
- 纵深防御（网络/应用/数据/环境多层）+ 最小权限 + 隐私优先

## 影响

- 正向：凭证零泄露、会话隔离、防滥用
- 约束：单用户 allowlist 未实现（test 环境暴露面受限，可接受）；密钥文件建议 0600 权限
- 关联：安全架构设计、C12 FeishuClient、REQ-SEC-*
