# ADR-004 部署形态：单体进程 + 多线程 + 子进程隔离

> 状态：已接受　类型：架构风格　日期：2026-08-05
> 架构阶段：环节 3（record_decisions）

## 背景

系统需承载事件回调、HTTP API、Web 页面、opencode 调用等能力，需决定部署形态。

## 决策

- **主方案**：单体 Python 进程（Flask threaded=True，单端口 5103），webhook 路由同步快速响应，业务处理派发 daemon 线程，opencode 以一次性子进程隔离执行。

## 权衡

| 维度 | 单体多线程（主） | 微服务/异步框架（备选） |
|------|------------------|--------------------------|
| 部署复杂度 | 单进程单端口，极简 | 多进程编排复杂 |
| 性能 | 单用户足够 | 高并发场景更优 |
| 上下文共享 | 内存态直接共享+锁 | 跨进程需通信 |
| 运维 | 简单 | 复杂 |

## 理由

- 存量代码即单体架构且稳定运行；SRS 02 明确「单用户+AI 助理模式」
- 12-Factor 适用：配置外部化（环境变量→YAML）、无状态服务模型（状态内存态）
- 端口约束（仅 5101/5102/5103）天然适配单端口聚合

## 影响

- 正向：部署/运维极简，零采购，端口占用最小化
- 约束：单点进程，高并发受 Python GIL 限制（单用户假设下可接受）
- 关联：物理视图 §2.4、容器视图、C4 HealthController
