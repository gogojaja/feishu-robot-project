# 安全架构设计 — 飞书机器人项目

> 依据：架构设计文档（数据与安全环节）· SRS REQ-SEC-*　角色：架构设计师　版本：v0.1　2026-08-05

## 1. 安全设计原则

- 最小权限：仅需 token/发送两类飞书 API 权限；无 sudo、无 /Users/gogo 路径（REQ-SEC-REQ-002）
- 纵深防御：接入校验 + 会话隔离 + 凭证保护 + 环境约束多层
- 隐私优先：消息不落盘（REQ-DATA-REQ-001）

## 2. STRIDE 威胁建模（六类全覆盖）

| 威胁类型 | 具体威胁 | 影响 | 现有/规划缓解 |
|----------|----------|------|--------------|
| S 仿冒 | 伪造飞书回调/重放 | 中 | challenge/token 校验；message_id 去重防重放 |
| T 篡改 | 事件内容被篡改 | 中 | 验证 token 比对；HTTPS 传输（ngrok/平台侧） |
| R 否认 | 调用无审计 | 低 | 关键事件日志留痕（REQ-NFR-REQ-002） |
| I 信息泄露 | 凭证/消息泄露 | 高 | 凭证仅内存、日志脱敏、消息不落盘 |
| D 拒绝服务 | 高频消息打爆/子进程耗尽 | 中 | open_id 限流（C10 待开发）；180s 超时终止 |
| E 权限提升 | 跨用户会话串访 | 高 | open_id 级会话隔离（REQ-SEC-REQ-004）；环境路径约束 |

## 3. 认证与授权

- **平台认证**：飞书应用 app_id/app_secret → tenant_access_token（OAuth2 client_credentials 类流程，REQ-FUNC-REQ-007）
- **入站校验**：url_verification challenge 原样回显（1 秒内）；事件校验 token
- **授权**：单用户模式，无 RBAC；最小权限集（im:message、发送、p2p 读等）
- **会话授权**：按 open_id 键控，禁止跨用户读取（REQ-SEC-REQ-004）

## 4. 数据安全（三要素）

| 要素 | 措施 |
|------|------|
| 保密性 | 传输层 HTTPS；凭证不落盘不写日志；消息内存态 |
| 完整性 | 飞书事件结构校验；challenge 校验 |
| 可用性 | 限流防滥用；超时兜底；health 探针 |

- **密钥管理**：app_secret 存 config/feishu.yaml（本地权限 0600 建议）或环境变量；优先级环境变量→YAML（REQ-ENV-REQ-002）
- **脱敏**：日志仅输出 open_id 与事件类型，不输出消息正文与凭证

## 6. 纵深防御（多层）

- **网络层**：HTTPS；端口仅开放 5103 单端口；禁 5001/5002/5003
- **应用层**：入站 4KB 校验（C11 待开发）；消息类型白名单（仅 text）；非文字友好拒绝
- **数据层**：零持久化；凭证内存态
- **环境层**：.env_type=test 核验；禁 /Users/gogo 与 sudo（AGENTS.md 安全审计）
