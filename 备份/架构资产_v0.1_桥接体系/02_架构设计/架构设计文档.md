## 1. 架构风格与总体策略

**风格**：单体应用（Monolithic）· 单进程 · 多线程（Flask threaded=True）· 门面式单类（FeishuBot 门面，逻辑内聚）

**理由**（源自策略分析结论）：
- 单用户低并发，无需微服务/异步框架
- 存量代码已稳定运行，保持可部署性优先
- 隐私约束（不落盘）决定状态全部内存态

**分层**：HTTP 接入层 → 服务核心层 → 外部适配层，全部位于单一进程内，按职责划分为逻辑组件（详见组件设计文档）。

### 2.2 进程视图（部署拓扑内单进程）
- **进程**：单一 Python 进程（feishu_integration.py），`app.run(threaded=True)`
- **线程**：主线程 = Flask WSGI；每个飞书事件经 webhook 路由立即返回，业务处理在独立 daemon 线程（`threading.Thread(target=self._process)`）
- **子进程**：每次调用 opencode 派生一次性 subprocess（180s 超时终止）
- **并发控制**：`_dedup_lock`（threading.Lock）保护 sessions/去重集合读写

### 2.3 开发视图（模块划分）
- 存量：单一模块 `src/feishu_integration.py`（334 行，FeishuBot 门面类）
- 架构预留模块化扩展点（开发阶段按需拆分，不强制当前重构）：
  - `session_manager.py`（会话/去重/限流，内存态）
  - `opencode_runner.py`（子进程调用+超时）
  - `output_sanitizer.py`（ANSI 清理+截断+代码块保护）
  - `feishu_client.py`（token/发送/告警重试）
- 扩展点遵循「功能边界清晰化」：新代码按模块组织，存量暂不破坏

## 4. 组件设计（详见组件设计文档.md）

| 组件 | 职责 | 关键接口 | 依赖 |
|------|------|----------|------|
| WebhookController | 事件接收/challenge/分发 | POST /feishu/events | 事件处理 |
| ApiController | HTTP 聊天接口 | POST /api/chat | 会话+OpenCode |
| PageController | Web 聊天页 | GET /chat | ApiController |
| HealthController | 存活探针 | GET /health | 无 |
| EventProcessor | 校验/非文字/会话查找/发送 | process(event) | 会话/去重/OpenCode/发送 |
| SessionManager | 会话/去重/限流 | get/put/check | 内存态+Lock |
| OpenCodeRunner | 子进程调用+超时+session 复用 | run(msg, sid) | 子进程 |
| OutputSanitizer | ANSI 清理+截断+代码块保护 | strip/truncate | 无 |
| FeishuClient | token/发送/告警/重试 | get_token/send | requests |
| RateLimiter | 固定窗口限流 | check(open_id) | 内存态 |

**通信原则**：组件间单向依赖，无循环依赖；全内存态无外部中间件；子进程每次独立派生。

## 6. 部署设计

- 环境：test（.env_type=test）；端口 5103；host 0.0.0.0
- 启动：`bash scripts/start-feishu.sh`；停止：`bash scripts/stop-feishu.sh`
