# 架构策略分析报告 — 飞书+OpenClaw+OpenCode（v0.3）

> 角色：架构设计师（analyze_strategy）｜依据：SRS v0.3（已固化）
> 版本：v0.3　日期：2026-08-12

## 1. 业务与技术背景

- 用户原始设想：飞书+OpenClaw+OpenCode 三件套，OpenClaw 作为中间网关统一调度
- 技术路线：自研 Python 桥接（webhook+ngrok）→ OpenClaw 官方 feishu 长连接 + ACP（决策已固化）
- 环境：仅 test（.env_type=test）；端口 5101/5102/5103（自研，已停用）+18789（OpenClaw 原生）

## 2. 约束梳理

- 业务：单用户+AI助理（项目负责人）；私聊白名单+群聊@触发
- 技术：OpenClaw 2026.7.1-2（Node26）；opencode CLI 1.17.4；@openclaw/feishu；@openclaw/acpx
- 功能：16 条 N-REQ（Must×9 / Should×7）
- 质量：可用性≥99%；P95≤15s；凭证保护；会话持久化
- 成本：零预算自研；无公网服务器（长连接免 ngrok）
- 时间：无强制外部节点，里程碑驱动

## 3. ATAM 权衡

| 权衡点 | 方案A（取） | 方案B（弃） | 理由 |
|--------|-------------|-------------|------|
| 事件接入 | OpenClaw 长连接 | 自研 Webhook+ngrok | 免公网、官方支持、无 ngrok 不稳定 |
| OpenCode 调用 | ACP adapter（acpx） | subprocess+--session | 官方协议、会话状态管理、持久化 |
| 会话存储 | OpenClaw 持久化映射 | 内存 dict | 重启恢复、设备接力 |
| 进程管理 | LaunchAgent 常驻 | 手动 nohup | 开机自启、状态可查 |

## 4. 技术选型结论

- **事件接入**：OpenClaw feishu 长连接（WebSocket），免公网
- **机器人中间层**：OpenClaw Gateway（含 Agent 编排/Skills/多模型/MCP/ACP）
- **OpenCode 集成**：ACP adapter（acpx 插件，persistent 模式）
- **会话**：OpenClaw chat↔session 映射持久化
- **权限**：dmPolicy=allowlist + permission 确认卡片 + requireMention
- **部署**：LaunchAgent 常驻 + openclaw gateway status 监控

## 5. 关键风险（详见架构风险登记册 ARCH-RISK-101~112）

- ACP 链路 smoke test 曾挂起（ARCH-RISK-103）——需诊断确认
- 飞书订阅切换长连接为入站前提（ARCH-RISK-110）
- 双通道重复回复风险（ARCH-RISK-109）
