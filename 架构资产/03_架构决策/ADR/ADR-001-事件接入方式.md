# ADR-001 事件接入方式：OpenClaw 长连接（WebSocket）

> 状态：已接受　类型：技术选型　日期：2026-08-12
> 架构阶段：环节 3（record_decisions）｜替代：旧 ADR-001（Webhook+ngrok，已废弃）

## 背景

飞书事件订阅支持 Webhook（需公网回拨）与长连接（WebSocket，官方推荐）。本项目 test 环境无公网 IP，采用 OpenClaw 官方 feishu 渠道（@openclaw/feishu）长连接接入。

## 决策

- **主方案**：OpenClaw feishu 长连接（WebSocket），事件 `im.message.receive_v1` 经长连接推送，免公网 IP/ngrok。
- **配套**：需在飞书开放平台将事件订阅方式从 webhook 改为「使用长连接接收事件」（方案 A）。
- **废弃**：自研 Flask Webhook + ngrok 穿透方案停用。

## 权衡

| 维度 | OpenClaw 长连接（取） | 自研 Webhook+ngrok（弃） |
|------|----------------------|--------------------------|
| 公网可达性 | 无需公网 IP | 依赖 ngrok 隧道 |
| 官方支持 | @openclaw/feishu 官方渠道 | 自研 |
| 稳定性 | 内建重连 | 隧道不稳 |
| 双通道 | 单通道（自研停用） | 双通道重复风险 |

## 理由

用户原始设想为 OpenClaw 统一网关；官方 feishu 渠道成熟稳定；长连接免公网符合零预算约束；N-REQ-01 要求长连接。

## 影响

- 正向：免 ngrok；与 OpenClaw 生态一致；Gateway 统一承载
- 负向：需用户在飞书后台切换订阅方式后方可入站
- 关联：N-REQ-01/N-REQ-16；ARCH-RISK-101/110
