# ADR-001 事件接入方式：Webhook 为主 + 长连接迁移预案

> 状态：已接受　类型：技术选型　日期：2026-08-05
> 架构阶段：环节 3（record_decisions）

## 背景

飞书开放平台事件订阅支持两种模式：**Webhook**（回调发送到开发者服务器）与**长连接**（WebSocket SDK，官方推荐）。本项目为 test 环境单机部署，无公网 IP/域名，需权衡接入成本与存量兼容。

## 决策

- **主方案**：Webhook 模式——Flask 接收 `POST /feishu/events`，url_verification 1 秒内原样返回 challenge；本地用 ngrok 内网穿透打通飞书回拨。
- **迁移预案**：生产环境升级为飞书官方长连接 SDK（WebSocket），免穿透、免解密验签。

## 权衡

| 维度 | Webhook（主） | 长连接（预案） |
|------|--------------|----------------|
| 公网可达性 | 需 ngrok 穿透 | 无需公网 IP |
| 存量兼容 | 完全复用现有路由 | 需引入 SDK 依赖 |
| 部署成本 | 依赖隧道稳定性 | 需维护 WebSocket 连接 |
| 安全 | 可配验签/解密 | 内置加密鉴权 |

## 理由

存量代码（`feishu_integration.py` v1.1）已实现 Webhook 路由并稳定运行；SRS 设计约束与现有架构保持一致。长连接作为生产迁移预案满足长期稳定性。

## 影响

- 正向：零采购、零重构，立即可用
- 约束：依赖 ngrok 隧道稳定性（风险 ARCH-RISK-001）
- 关联：C1 WebhookController、接口设计文档 §2.1
