# 数据架构设计 — 飞书机器人项目

> 依据：架构设计文档（数据与安全环节）· SRS REQ-DATA-REQ-001　角色：架构设计师　版本：v0.1　2026-08-05

## 1. 数据架构总原则

**「不落盘」原则（REQ-DATA-REQ-001）**：消息内容、会话上下文、token 全部仅存内存态，进程退出即时销毁；磁盘上不写任何消息文本。

## 2. 数据模型（内存态，ER 描述）

### 实体关系
```
FeishuUser(open_id) ──1:N──> Session(open_code_sid)
Event(message_id) ──1:1──> 幂等去重标记
OpenID ──1:N──> RateLimitWindow（固定窗口计数）
```

### 数据字典（内存对象）

| 对象 | 字段 | 类型 | 约束/默认 | 生命周期 |
|------|------|------|-----------|----------|
| Session | open_id→opencode_sid | dict[str,str] | 唯一主键=open_id | 进程内；按需更新 |
| Dedup | message_id | set[str] | 幂等键 | 进程内累积 |
| Token | tenant_access_token, token_expire_time | str,int | expire=+7200s | 过期自动刷新 |
| RateLimit | open_id→(window_start,count) | dict | 窗口 60s/10 条 | 窗口滑动重置 |

### 数据结构化存储：无
- 无数据库、无缓存中间件、无配置文件写回
- config/feishu.yaml 仅存凭证与端口（读取不写回）

## 3. 存储策略

| 决策项 | 方案 | 理由 |
|--------|------|------|
| 数据库 | 无 | 隐私约束 + 零采购 + 单用户 |
| 会话存储 | 内存 dict + threading.Lock | REQ-FUNC-REQ-013 |
| 缓存 | 无 | 非必需 |
| 配置 | 环境变量优先 → YAML 只读 | REQ-ENV-REQ-002 |

## 4. 数据流转图（内存态）

```
飞书事件 ──► C11 入站校验(>4KB拒绝) ──► C7 去重 ──► C5 取会话 ──► C8 opencode
    │                                                                  │
    └─────────────── C12 发送回复 ◄── C9 输出清理/截断 ◄──────────────────┘
                    (内存态 token)
```

## 5. 数据生命周期

- **创建**：消息到达 → Session/Dedup/RateLimit 记录创建
- **使用**：单次请求内完成读写，全部内存
- **归档**：无（不落盘）
- **销毁**：进程退出即销毁；超长会话不清理（单用户规模可接受，风险 ARCH-RISK-010）

## 6. 合规

- 隐私：消息内容零持久化 ✅（REQ-DATA-REQ-001）
- 数据分级：全部为运行时瞬态数据，无敏感历史留存
- 删除要求：进程重启即完全清空 ✅
