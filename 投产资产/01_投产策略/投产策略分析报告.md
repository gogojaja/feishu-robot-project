# 投产策略分析报告 — M6 投产部署（test 环境）

> 依据：role-deployment strategy.md · 项目范围基准（仅 test 环境）· 版本：v1.0　日期：2026-08-06

## 1. 部署策略选型

| 项目 | 判定 |
|------|------|
| 系统定位 | 非核心桥接服务（飞书→OpenCode），test 环境 |
| 变更规模 | 单体 Flask 单文件（src/feishu_integration.py 403 行）+ 脚本 + 配置 |
| 停机容忍 | 可接受短停（test 环境） |
| 选定策略 | **大爆炸（Big Bang）+ 备份回滚** |
| 选型理由 | 单文件无状态服务、test 环境可停机、回滚=备份覆盖（≤5 分钟）、无灰度/流量控制基础设施需求；范围基准明确「不部署生产环境」 |

## 2. 投产风险评估矩阵

| 风险 | 影响 | 概率 | 等级 | 应对 |
|------|:---:|:---:|:---:|------|
| 启动失败（依赖/端口冲突） | 严重(3) | 低(2) | 中(6) | 启动前 check_env 核验；日志定位；从备份回滚 |
| 飞书回调链路异常 | 一般(2) | 低(2) | 中(4) | 测试用例冒烟 + 真实事件 POST 验证 |
| 配置泄露（app_secret 明文） | 致命(4) | 低(2) | 高(8) | 仅 test 环境；不提交生产凭证；README 提示轮换 |
| opencode serve 不可用 | 严重(3) | 低(2) | 中(6) | start 脚本等待就绪 + 健康检查；重启 serve |
| 回滚失败 | 一般(2) | 极低(1) | 低(2) | 备份双份（M4/M5）+ git 版本双保险 |

## 3. 回滚预案设计

- 触发：健康检查失败 / 事件回调 5xx 持续 / 桥接响应异常
- 步骤：stop-feishu.sh → 备份当前 → git checkout 上一 commit → start-feishu.sh → health 验证
- 目标：≤5 分钟
- 决策人：段波（项目负责人）/ AI 助理（执行）

## 4. DORA 基线评估

| 指标 | 定义 | 目标 |
|------|------|------|
| 部署频率 | 成功发布频率 | 按需 |
| 变更交付时间 | 提交→投产 | <1h |
| 变更失败率 | 导致故障部署占比 | <5% |
| 服务恢复时间 | 故障到恢复 | <1h |

## 5. 灾备验证（ISO 22301 裁剪）

- test 环境：RTO ≤15 分钟（备份覆盖重启）、RPO 无业务数据（无 DB 业务数据，仅 opencode.db 会话库，非核心）
- 投产前演练：回滚演练 1 次（本次投产步骤中同步完成）

## 6. 结论

大爆炸策略适用于单文件 test 环境桥接服务；风险可控，回滚 ≤5 分钟；DoD 满足后进入《投产方案》编写。
