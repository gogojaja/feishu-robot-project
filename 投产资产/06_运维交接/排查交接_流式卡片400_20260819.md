## 0. 一句话结论

**已解决**。根因：`cardkit:card:write` 仅授权为 **user 身份**（scope_type=user），未授权 **tenant 身份**；OpenClaw 用 tenant_access_token 调用 → 报 99991672「应用尚未开通所需的应用身份权限」。处置：飞书开放平台权限管理将 cardkit:card:write 加入 tenant 数组 → 发布新版本 → 重启 Gateway 验证通过。

> 修正：初版交接文档 §3.4 猜测根因为「正式版权限快照不含」，实测发现真正根因是 **scope_type 不匹配（user vs tenant）**，比原猜测更精确、更易修复。

## 3. 证据链（已完整走查）

### 3.1 出错代码点（openclaw 源码）
- 文件：`/opt/homebrew/lib/node_modules/openclaw/dist/monitor.account-N9APk6Vp.js`
- 请求：`start()` line 1084-1106，`POST {apiBase}/cardkit/v1/cards`，body `{type:"card_json", data: JSON.stringify(cardJson)}`
- 抛错：line 1109 `if (!createRes.ok) throw new Error(...)`
- 卡片 JSON：`schema:2.0` + `config.streaming_mode:true`（line 1065-1076）
- 流式开关判定：line 1655-1656
  `renderMode = account.config?.renderMode ?? "auto"`
  `streamingEnabled = account.config?.streaming !== false && renderMode !== "raw"`
  （当前 account 仅 appId/appSecret，两开关均为默认 → 流式默认开启）

### 3.2 实测复现（真实凭证脚本，非猜测）
- 直接调用 `cardkit/v1/cards` → **400 code=99991672**，msg 明确「应用尚未开通所需的应用身份权限：cardkit:card:write」
- 返回体 `error.permission_violations`: `[{type:"action_scope_required", subject:"cardkit:card:write"}]`
- 对照：`GET application/v6/scopes`（官方「查询租户授权状态」接口）→ **cardkit:card:write grant_status=1（已授权）**，共 8 个权限全部授权
- 对照：`im/v1/chats` 也报 99991672（预期，该应用无 `im:chat:read`）→ 证明 token 机制与错误上报本身正常

### 3.3 已排除项（避免接手人重复试验）
| 排除项 | 排除依据 |
|---|---|
| ❌ token 缓存 | 重启 Gateway + 每次全新 `tenant_access_token` 复测仍 400 |
| ❌ appSecret/appId 错误 | token 获取正常（code=0） |
| ❌ 应用身份错位 | 错误返回体 helps URL 与配置 appId 均为 `cli_aa82c1b457b89bc3` |
| ❌ 非流式卡片不可用 | 回退非流式卡片送达正常（replies=1） |
| ❌ 域名/网络 | `open.feishu.cn` 正常访问 |

### 3.4 待验证根因（接手人主攻方向，按概率排序）
1. **已发布正式版本的权限快照不含 cardkit:card:write**（最高概率）。飞书机制：运行时权限取决于「当前已生效/已安装版本」的权限快照；`application/v6/scopes` 反映开发/测试侧租户授权，与正式版快照可能不一致。用户已确认发布，但需核对**最新已生效版本的权限清单里是否确实列出 cardkit:card:write**（若权限是在测试版/测试企业开通，正式版不继承）。
2. **应用能力未开启**：飞书要求流式卡片须「应用能力 → 机器人 + 卡片」具备；机器人能力已开（收发正常），卡片能力存在与否未在平台侧核实。
3. **飞书平台侧权限生效延迟/灰度**：等待数小时后再实测一次可验证。

## 4. 处置选项（供 L2 决策，二选一）

### 选项 A：本地禁用流式卡片（推荐，可立即闭环，无需平台操作）
- 改 `~/.openclaw/openclaw.json` → `channels.feishu.accounts.default` 增加 `"streaming": false`
- 效果：不再发起 cardkit 请求，回复一次送达，0 ERROR 日志（等于固化现有正常回退行为）
- 代价：无「生成中」进度效果
- 回滚：删除该字段 + 重启 gateway 即复原

### 选项 B：平台侧根治流式卡片
- 在飞书开放平台核对/补开：正式版「版本管理与发布」权限快照须含 `cardkit:card:write`，且应用能力含卡片；必要时创建新版本发布
- 需 L2 在平台操作一次；完成后重跑 §3.2 复现脚本验证
