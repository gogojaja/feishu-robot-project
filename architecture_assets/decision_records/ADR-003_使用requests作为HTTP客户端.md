ADR-003: 使用 requests 作为 HTTP 客户端

**日期**: 2026-08-12
**状态**: Accepted
**决策者**: 架构师

## 上下文

本项目需要调用飞书 API 和 OpenCode API，需要选择一个 HTTP 客户端库。

考虑过的备选方案：
1. **requests**: 标准 HTTP 库、API 简洁、性能优秀
2. **httpx**: 异步 HTTP 客户端、性能更好
3. **urllib3**: 低级 HTTP 库、功能强大但复杂

## 决策

最终选择 **requests** 作为 HTTP 客户端。

**理由**：
1. 标准 HTTP 库：Python 标准 HTTP 库
2. API 简洁：API 简洁易用
3. 性能优秀：性能优秀
4. 文档丰富：文档丰富，社区支持好
5. 成熟稳定：成熟稳定，生产案例丰富

## 选项（Options Considered）

### 方案 A: requests
- **优点**: 标准 HTTP 库、API 简洁、性能优秀、文档丰富
- **缺点**: 无异步支持
- **评分**: 5.00

### 方案 B: httpx
- **优点**: 异步 HTTP 客户端、性能更好
- **缺点**: 需要异步编程、生态相对较小
- **评分**: 4.00

### 方案 C: urllib3
- **优点**: 功能强大、性能优秀
- **缺点**: API 复杂、学习成本高
- **评分**: 4.25

## 驱动因素

- **简洁性**: API 简洁易用
- **性能**: 性能优秀
- **生态**: 文档丰富，社区支持好
- **成熟度**: 成熟稳定，生产案例丰富

## 后果

**正面后果**：
- API 简洁易用
- 性能优秀
- 文档丰富，社区支持好

**负面后果**：
- 无异步支持（本项目不需要异步）

**风险与缓解**：
- **风险**: 无异步支持
- **缓解**: 本项目不需要异步，同步调用足够
